Design pass · full system

Many blocks, many villages, many products — and a DDU can span more than one village.

A Block holds several Vatikas; each Vatika surfaces several products; a product that clears assessment and pricing becomes a DDU — usually for one Vatika, but when one village can't cover the order alone, two or more can pool their Vaibhavis into a single merged DDU instead. The sections just below lay that out before anything else: how the five stages feed each other in a loop, how Block, Vatika, product and DDU nest inside one another, and exactly how a merge gets built. Everything after that — role journeys, then each stage in detail — sits on top of that map.

How the pieces connect

Not a one-way pipeline — a loop. What a live DDU sells teaches the next round of opportunity mapping where to look.

The dashed arrow closes the loop: what a live DDU actually sells, and which products match across a Block's Vatikas, feed straight back into where the next Opportunity Mapping survey looks — and sometimes into merging two villages into one larger DDU instead of surveying them separately.

Block → Vatika → Product → DDU

One Block holds several Vatikas; one Vatika surfaces several products; one product that clears assessment and pricing becomes one DDU. Browse the containment, then see every DDU flattened into one list.

The convention, fixed everywhere in the app — code, copy, and this document: one Vatika is exactly one village. One Block contains several Vatikas (several villages). One District contains several Blocks. Never the reverse, never a shortcut past a level — a Vasuki can cover several Blocks, but a Block is never smaller than the Vatikas inside it.

Roles, KRAs & the transparency line

The rule behind every screen in this app: full transparency, boundaried KRAs. Anyone can see the data that gives their own job context — but each role edits only its own Key Result Area, and a Home page only ever instructs you on your KRA, never someone else's.

Key Result Areas, by role and level

SWSM Village Products needing Stage 2 or Cost Economics in my villages Stage 2, Cost Economics (my assigned Vatikas only) Stage 1 raw data (informs Part A), Stage 3 progress (to see where my call led) Villages outside my list; assignment policy; other SWSMs' villages

Note the asymmetry on purpose: a Vasuki sees Stage 2's verdict but can't edit it; a Mitra sees support needs but never a rupee figure; a Dhawak sees every DDU's demand in his district but nothing about how its price was set. Nobody is ever blocked from the context their job needs — and nobody can touch what isn't theirs.

Gaps this pass closes

found by walking the built app, not guessed
Status chips, no substance
You could see a stage was "Done" — never what was actually in it

The product profile and Home board only ever showed a chip (done/partial/blocked) and a one-line count. Seeing the real shop name, the real priority score, or who set a price meant navigating into someone else's edit form. Every stage row now expands in place into the real filled data — with who filled it and when — and Home rows carry a live one-line recap (demand, capacity, profit, or priority/critical outcome) instead of just chips.

Cross-stage blindness
Filling Stage 3 with no idea what Stage 2 or pricing had decided

Stage 2 and Stage 3's own wizards had zero visibility into earlier work — a Vasuki building Stage 3 couldn't see SWSM's assessment or the price verdict without leaving the page, and SWSM assessing Stage 2 couldn't see what Stage 1 had actually found. Both wizards now carry a collapsible "what came before" recap right at the top.

Missing entry point
Products could only ever be created by accident

Stage 1 free-text entry was the only way a product came into existence — auto-created with a placeholder icon/category, no way to clean it up. Admin now gets a Products catalog: browse, fix category/icon/unit, or add one directly. Two entry points, same underlying table.

Missing entry point, then a save bug
Assignment policy was read-only — then felt broken

AdminUsers showed each person's District/Block/Vatika coverage but had no way to change it. An Assignments screen closed that gap — but its first cut needed a separate "Save" tap per row, easy to miss, so a toggle that hadn't been confirmed looked like it silently reverted. It now saves the instant you tap, same live-update feel as Cost Economics, with a brief "Saved ✓" flash.

Missing entry point
Geography could be browsed but never grown

Every screen could show a District, Block or Vatika that already existed in the seed data — none could create one. Blocks & Vatikas now has "+ Add a district," "+ Add a Block" under each district, and "+ Add a Vatika (village)" inside a Block's own page — each new unit appears the instant it's created, no page reload needed.

Uninstructed home page, part 2
Home showed what existed — not what's new or still missing

Even after the KRA banner and "needs you" split, Home only ever listed products that already had at least one stage filled in. A product from the catalog nobody had surveyed yet, anywhere in your Block or village, was invisible. Home now opens with a count strip — needs you, live, for awareness, not started — and a "new DDU opportunities" row naming exactly which catalog products are still unsurveyed in your own area.

Desktop-only
Admin only really worked at a desk

The Admin sidebar collapsed to a cramped single row on a phone with no visible way to log out, and no page below it had been checked at phone width. Every Admin screen — dashboard, Blocks & Vatikas, Products, Users, Assignments, DDU detail — now has a mobile top bar with a working log-out button, a horizontally-scrollable nav row, and tables that scroll inside their own frame instead of stretching the page.

No provenance
Overriding a price with no idea who set it, or how it compares

The Cost Economics override panel showed only the current numbers. It now shows who filled each input and when, plus — if the same product is priced elsewhere — a side-by-side of those other DDUs' verdicts, so Admin never overrides blind.

Flattened view
District-level shouldn't mean one flat list

Dhawak's "This week's pickups" was a single flat list regardless of how many Vatikas his district spans. It now groups by Vatika or by product, his choice — district level should mean *more* ways to slice the same data, not just a longer list.

Uninstructed home page
Every role saw the same board

Home showed all four stage chips for every product to every role alike, with no framing of which stage was actually this person's job. Home now opens with a one-line KRA reminder and separates "needs you" from "for your awareness" instead of one undifferentiated list.

Reading this mockup

  • Ledger-style sections (Stage 1 product rows, Stage 3 Demand/Supplier) are shown as one grouped entry screen plus a running list — practical for logging many rows in one sitting, not one question per screen.
  • Cost Economics uses the exact formulas and one worked example (Cloth Tote Bags) from the shared pricing tool; Amla Murabba is a second, invented example to show the GO path.
  • The "Merging Vatikas" section is not a proposal — its screens mirror the built app exactly: Devgaon + Sonpur really is one DDUGroup record, 3,840 is really 2,640 + 1,200 summed by the model, and ₹1,377 is the real computed monthly profit, verified end to end.
  • Role levels (District/Block/Village chips in Role Journeys) are likewise verified against the running app, including the "never repeat yourself" fix — a product picked once no longer has to be found again to log more Stage 1 data against it.
  • Colour system: warm oat ground, marigold for field-app actions, deep petrol teal for Admin/section tabs — Cost Economics screens borrow an amber "money" tag to read as a distinct, serious step.
  • Not yet drawn: Block-level survey's business-mapping step before its institution survey, and a dedicated Sakhya-leads list — same visual language, to follow.
  • Latest pass, verified end to end on the running app: Assignment policy now auto-saves per tap; District/Block/Vatika can all be created from the Admin console (not just viewed) and appear immediately, no reload; every Home page opens with a needs-you / live / for-awareness / not-started count strip plus a named list of catalog products nobody's surveyed yet in your own area; every Admin screen was checked at phone width (375px) with no page-level horizontal scroll and a reachable log-out button. A real performance bug was also found and fixed in this pass — the Admin "All DDUs" list was fetching each Vatika's data one at a time instead of all at once, which alone had been stretching its load time past two seconds.
  • Newest pass: a brand-new District/Block/Vatika now starts covered — every existing Dhawak gets a new District automatically, every Vasuki/Vidushi gets a new Block, every SWSM/Mitra gets a new Vatika, so nothing created from the Geography page is orphaned with no one able to act on it (Admin can still narrow coverage afterwards). Every stage screen (Home, product profile, Stage 2, Cost Economics, Stage 3) now surfaces the real filled data — not just a status chip — with who filled it and when, so any role can see what another role already decided without needing edit access to see it. Also fixed a stale-cache crash in Assignment policy (a browser holding data saved before a schema change) by hardening the save path and bumping the data version.
